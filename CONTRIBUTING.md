# Contributing to OpenFolk

Thank you for taking the time to contribute. This guide applies to every repository in the OpenFolk organization unless the repository ships its own.

## Before you start

- **Bugs and ideas** go into the issue tracker of the affected repository. Please use the templates; they ask for the details we need to reproduce or evaluate.
- **Security issues** must not be reported publicly. See [SECURITY.md](SECURITY.md).
- **Bigger changes** (new features, architectural changes) start with an issue so we can agree on the approach before you invest time.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep the change focused. One topic per pull request makes review fast.
3. Follow the existing style of the code you touch: same naming, same comment density, same idioms.
4. Add or update tests where the repository has them, and make sure the existing test suite passes.
5. Describe in the pull request *what* changes and *why*. Link the related issue.
6. Be prepared for review feedback; we try to respond within a few days.

## Commit messages

Use the imperative mood in the subject line ("Add approval timeout", not "Added"). Keep the subject under 72 characters and explain the reasoning in the body if it is not obvious from the diff.

## Licensing

By contributing you agree that your contribution is licensed under the license of the repository you contribute to. Repositories that are also offered under a commercial license, such as [OpenFolk](https://github.com/OpenFolk/OpenFolk), ask you to sign a Contributor License Agreement with your first pull request instead; their own `CONTRIBUTING.md` explains it.

## Code of conduct

Everyone participating in OpenFolk projects is expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
